# Как работать с проектом

## 1. Что установить

| Программа | Версия | Зачем |
|---|---|---|
| PHP | Версия, используемая проектом | Запуск приложения |
| Git | Актуальная стабильная версия | Клонирование репозитория и работа с версиями проекта |
| Visual Studio Code | Актуальная стабильная версия | Редактирование исходного кода |
| PHP_CodeSniffer | 4.0.4 | Проверка соответствия PHP-кода стандарту PSR-12 |
| Apache / Nginx | Согласно конфигурации проекта | Локальный запуск приложения |
| СУБД | Согласно конфигурации проекта | Хранение данных приложения |
| NetBeans | Актуальная стабильная версия | Альтернативная среда разработки |

## 2. Как запустить проект

1. Установите необходимые программы из раздела 1.
2. Клонируйте репозиторий:

   ```bash
   git clone <ссылка-на-репозиторий>
   ```

3. Перейдите в папку проекта:

   ```bash
   cd <название-проекта>
   ```

4. Настройте локальное окружение согласно конфигурации проекта.
5. Создайте базу данных и настройте подключение к ней.
6. Выполните импорт структуры базы данных и тестовых данных (если они предусмотрены проектом).
7. Настройте веб-сервер и укажите корневую директорию проекта.
8. Запустите локальный сервер и откройте приложение в браузере по адресу, указанному в конфигурации.
9. Проверьте работоспособность приложения.

Тестовые пользователи и пароли должны быть указаны в документации проекта или в файле с тестовыми данными.

## 3. Настройки редактора

- В проекте лежат `.editorconfig` и `.vscode/`.
- `.editorconfig` задаёт единые правила форматирования исходного кода, включая отступы и окончания строк.
- `.vscode/settings.json` содержит настройки редактора Visual Studio Code для текущего проекта.
- `.vscode/extensions.json` содержит список рекомендуемых расширений.

После открытия проекта в VS Code необходимо установить предложенные рекомендуемые расширения и проверить, что настройки проекта применились.

Для второй IDE (NetBeans) используются настройки форматирования на уровне проекта:
- размер отступа — 4 пробела;
- преобразование табуляции в пробелы (Expand Tabs to Spaces).

Необходимо открыть настройки форматирования проекта в NetBeans и убедиться, что указанные параметры применены.

## 4. Проверка стиля кода

Для проверки используется PHP_CodeSniffer версии 4.0.4.

Команды выполняются из корневой папки проекта:

```bash
# Проверка кода — краткий отчёт
php phpcs.phar --report=summary

# Проверка кода — подробный отчёт
php phpcs.phar --report=source

# Автоматическое исправление нарушений
php phpcbf.phar
```

Перед каждым коммитом:
1. Запустить проверку PHP_CodeSniffer.
2. Исправить обнаруженные нарушения.
3. Проверить изменения командой `git diff`.
4. Убедиться, что форматирование не изменило логику работы приложения.

Если автоматическое исправление невозможно, исправить нарушения вручную.

## 5. Ветки и коммиты

- Ветки: для основных изменений использовать отдельные ветки. Например: `practice/m04`, `fix/loan-limit`, `feature/new-functionality`.
- Сообщения коммитов должны кратко описывать внесённые изменения:
  - `style: ...` — форматирование и стиль кода;
  - `refactor: ...` — изменение структуры кода без изменения поведения;
  - `fix: ...` — исправление ошибок;
  - `docs: ...` — изменения документации;
  - `feat: ...` — добавление функциональности.
- Изменения форматирования и изменения логики желательно разделять на разные коммиты, чтобы упростить проверку и анализ истории изменений.

Перед отправкой изменений необходимо проверить `git status` и убедиться, что в коммит попадают только необходимые файлы.

## 6. Чего не коммитить

Не добавлять в репозиторий:

- персональные настройки IDE, не относящиеся к проекту;
- временные файлы и резервные копии;
- логи и файлы отладки;
- кэш приложения;
- временные файлы операционной системы;
- локальные конфигурации с паролями и секретными ключами;
- дампы баз данных с реальными персональными данными;
- зависимости и сгенерированные файлы, если они могут быть восстановлены автоматически.

Перед коммитом проверять список изменений командой:

```bash
git status
```

В репозитории должны находиться только файлы, необходимые для совместной разработки и запуска проекта.
